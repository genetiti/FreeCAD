# Phase 2 — UI Design Contract

> Visual and interaction contract for the FreeWorks CommandManager ribbon (`FwRibbon`).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Platform note:** This is a C++20 / Qt 6.8 desktop CAD application, not a web project.
> The shadcn / web-token sections of the template are mapped onto their Qt equivalents:
> "components" = Qt widgets, "spacing scale" = layout/metric tokens in device-independent
> px, "typography" = `QFont` roles, "color" = the QPalette/QSS accent values the ribbon
> depends on. shadcn is **not applicable** (no React/Next/Vite). Final pixel-perfect SW
> theming (exact blue, fonts, button chrome) is **Phase 7**; this phase fixes only the
> structural metrics + behavior the ribbon needs to read as "this is SolidWorks" and to
> not fight Phase 7's restyle. Values below are deliberately structural, theme-overridable.

## Spacing Scale

Ribbon layout metrics in device-independent pixels (scale with Qt HiDPI / `devicePixelRatio`
automatically). Multiples of 4 unless an SW-fidelity exception is noted.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Padding inside a button (icon-to-label gap, edge inset) |
| sm | 8px | Gap between buttons within a panel group |
| md | 16px | Gap between panel groups within a tab (with separator) |
| lg | 24px | (reserved) larger intra-tab break if a panel needs visual isolation |

Component metric tokens (the values the ribbon contract actually pins):

| Metric | Value | Usage |
|--------|-------|-------|
| Large button icon | 32px | Primary "large" command button icon (SW large-icon feel; FreeCAD default toolbar icon is 24px — the ribbon must be visibly bigger than a stock toolbar). |
| Small/flyout-row icon | 16px | Icons inside an open flyout list and any small/secondary buttons |
| Large button min size | 56×72px | Min footprint of a large icon-over-label button (icon block + 2 text lines) |
| Tab bar height | 28–32px | Tab strip across the top of the ribbon |
| Ribbon panel height | 88–96px | Total ribbon body height for one row of large buttons + panel title strip |
| Panel group separator | 1px | Vertical divider between adjacent panel groups |
| Flyout split-button arrow zone | 16px wide | The dropdown-arrow hit region of a split button (distinct from the primary-action zone) |
| Touch/pointer target min | 24px | Minimum hit target for any clickable ribbon element |

Exceptions: large-button icon (32px), the 56×72 / 88–96 ribbon-body metrics, and the 1px
panel group separator are **SW-fidelity exceptions** to the 4-multiple spacing scale — they
are sizing constants chosen to make the ribbon read as a SolidWorks CommandManager rather
than a thick toolbar. Specifically:
- 32px large-button icon, 56×72 large-button footprint, 88–96 ribbon-body height —
  SW-fidelity sizing so the ribbon reads bigger than a stock FreeCAD toolbar.
- 1px panel group separator — SW-fidelity exception; hairline divider matching SolidWorks
  panel chrome convention (not a layout spacing token).

All are theme-overridable in Phase 7.

## Typography

Qt `QFont` roles for ribbon text. Sizes are points (pt) at 100% scale; Qt scales for HiDPI.
NO custom font family this phase (system UI font). 2 weights max.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Button label | 9pt | Regular (400) | up to 2 lines, word-wrapped, centered under icon |
| Tab label | 9pt | Regular (400) | single line |
| Active tab label | 9pt | Medium/Semibold (600) | single line — weight is the active-tab affordance until Phase 7 adds the blue underline/accent |
| Panel group title | 8pt | Regular (400) | single line, centered below the panel's buttons |

Notes:
- Button labels MUST wrap to a second line (e.g. "Extruded\nBoss/Base"), never truncate with
  an ellipsis — SW command names are long and recognizability depends on the full label.
- Exactly 2 weights are in play: Regular (400) and Semibold (600, active-tab only).
- Button-label line height is governed by Qt's `QFontMetrics` defaults at 9pt; no numeric
  override this phase. Phase 7 may introduce an explicit `setLineHeight()` if the system
  metric produces visual crowding.

## Color

This phase does NOT introduce a final theme (Phase 7 owns the SW blue accent, panel chrome,
fonts). The ribbon MUST render correctly on the **current FreeCAD QPalette** (inherits the
user's active FreeCAD theme — light or dark). The contract here is the 60/30/10 *role
assignment* the ribbon depends on, expressed as palette roles, so Phase 7 can re-skin without
the ribbon's structure changing.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `QPalette::Window` (inherited theme background) | Ribbon body + tab strip background |
| Secondary (30%) | `QPalette::Button` / `QPalette::Base` | Button faces, panel-group surfaces, hover/pressed states via native `QStyle` |
| Accent (10%) | `QPalette::Highlight` (inherited; Phase 7 replaces with SW blue) | **Active-tab indicator and button hover/checked highlight ONLY** |
| Destructive | not applicable | No destructive actions exist in this phase (see Copywriting) |

Primary focal point: the active-tab indicator + large icon-over-label buttons are the dominant
visual anchors; the accent color on the active tab is the strongest eye-draw element.

Accent reserved for: the **active ribbon tab indicator** and the **hover/pressed/checked state
of a ribbon button** — nothing else. The ribbon must NOT hard-code any hex color this phase;
all color flows through the inherited `QPalette` / native `QStyle` so it stays correct in both
light and dark FreeCAD themes and so Phase 7 can swap in the SW blue centrally.

## Copywriting Contract

Ribbon command labels come from the FreeCAD command registry (`Command::getMenuText()` /
action text) — they are NOT re-authored here (Context D-05/D-08: only real command IDs are
placed, no extras). The copy this phase owns is the **chrome** (tab names, panel-group titles,
the discoverability escape hatch from D-12, and tab-switch behavior messaging). No "SolidWorks"
string may appear anywhere (CI leak-grep gate, Phase 1 D-03).

| Element | Copy |
|---------|------|
| Primary CTA | n/a — the ribbon has no single CTA; its "primary action" is firing the command under a clicked button (label sourced from the registry). |
| Curated tab names | `Features`, `Sketch`, `Evaluate` (core modeling loop; `Surfaces` optional per D-06). Names match the SW default roster; verify the exact SW2024/2025 roster at plan time per D-05. |
| Panel-group titles | Authored in the curated map per panel (e.g. under Features: a primary feature-creation panel; under Sketch: a sketch-entity panel). Use plain, SW-faithful nouns; final roster set at plan time against version-pinned SW Help. |
| Empty state heading | "No commands available for this workbench" |
| Empty state body | Shown only if a workbench yields no derivable tabs (should not happen given the auto-derive fallback D-07): "Switch to a modeling workbench, or use the menu/keyboard shortcuts to run commands." |
| Discoverability escape hatch (D-12) | Because the menu bar + toolbars are hidden in FreeWorks mode (D-11) but only the core loop is curated (D-06), commands off a curated tab MUST stay reachable. Minimum: all existing FreeCAD keyboard shortcuts keep working. Affordance label if an overflow/search is provided: "More commands…" — exact mechanism (shortcuts-only vs command-search vs overflow) is Claude's discretion, decided at plan review. |
| Error state | If a curated command ID resolves to no registered command, it is **silently omitted** (D-08 omit-missing) — no error UI shown to the user; record the gap as a planning note for a future phase. |
| Destructive confirmation | n/a — no destructive action in this phase. Ribbon buttons are thin triggers into `Gui::Command`/`CommandManager`; any destructive command carries its own existing confirmation downstream. |

Behavioral copy / state contract (RIBBON-02, Context D-09/D-10):
- Entering sketch-edit auto-activates the `Sketch` tab (context wins over a manual selection).
- Leaving sketch-edit restores the tab that was active before entering — no toast/message; the
  switch is silent and immediate, matching SW.

## Registry Safety

"Registry" here = third-party C++/Qt dependencies pulled into the build for this phase, not a
shadcn component registry (not applicable).

| Registry | Blocks Used | Safety Gate |
|----------|-------------|-------------|
| Qt 6.8 Widgets (in-tree dependency) | `QTabWidget`, `QToolBar`, `QToolButton` (split-button menus), hosted on `Gui::ToolBarAreaWidget` | not required (existing project dependency) |
| FreeCAD command registry (in-tree) | `ToolBarItem`/`MenuItem` trees, `CommandManager`, `BitmapFactory` | not required (existing project dependency; observe-the-DOM, no backend duplication per D-05) |
| SARibbon (MIT v2.8.0) — **conditional fallback only** | Full ribbon widget, IF and only IF the native spike (D-02/D-03) fails | **vendor-vetting gate required before adoption**: vendor as git submodule at `src/3rdParty/SARibbon` + single `add_subdirectory` (D-04); confirm MIT license + pin v2.8.0; clear `tools/fw-string-leak-grep.sh` and `tools/fw-provenance-guard.sh`; no Pixi/Conda dep (tri-OS reproducibility). NOT adopted unless the spike fails — default path is native (D-01). |

No third-party shadcn-style block registries are in scope. No network/eval/env-access vetting
applies (no fetched UI blocks). The SARibbon decision is a build-dependency decision gated by
the spike, recorded here so the planner does not need a second decision round.
