<objective>
Wire the ribbon into the live window as a single command surface: mount `FwRibbon` by WRAPPING it in a real `Gui::ToolBar`/`QToolBar` and calling `Gui::getMainWindow()->addToolBar(Qt::TopToolBarArea, wrapper)` from `FwLayout`/`FwWorkbench`, hide FreeCAD's menu bar + toolbars reversibly in FreeWorks mode (D-11), add the discoverability escape hatch so no command is stranded (D-12), and make the layout persist across restarts (D-14). After this plan, launching FreeWorks mode shows the ribbon *replacing* menus+toolbars, switching away cleanly restores stock chrome, and the ribbon's tab/panel state survives a restart — the end-to-end "ribbon is the app's command surface" slice. Context tab switching is Plan 04.

> **Mount & persistence correction (REVIEW concerns 3 & 4 — load-bearing; this was the riskiest plan):** The original plan mounted a plain `FwRibbon : QTabWidget` into a `ToolBarAreaWidget` via `toolBarAreaWidget(...)`, treating that method as a `TopToolBarArea` enum lookup and assuming `QMainWindow::saveState()` would persist it. Both are wrong in this checkout: (1) `ToolBarManager::toolBarAreaWidget(QWidget*)` takes a widget and returns the area *containing* it — it is NOT an enum lookup for `TopToolBarArea` (verified: `ToolBarManager.h:181`). (2) `QMainWindow::saveState()` only serializes dock widgets and real `QToolBar`s; FreeCAD's `ToolBarAreaWidget::saveState()` likewise iterates only `QToolBar` children (verified: `ToolBarAreaWidget.cpp:121`) — a plain `QTabWidget` child does not round-trip, so D-14/SC5 could fail with all headless tests green. The fix (per review): wrap the ribbon in a real `QToolBar` (stable objectName `Fw_RibbonToolBar`) added via `addToolBar(Qt::TopToolBarArea, ...)` so Qt owns a genuine state participant, and persist tab-selection/panel state separately via a ParameterGrp key.

Purpose: RIBBON-01 Success Criteria 1 ("replacing FreeCAD's menus+toolbars") and 5 (layout persists; survives upstream sync as a self-contained widget); CONTEXT D-11/D-12/D-14.
Output: extended `FwLayout.{h,cpp}` (wrap+addToolBar mount + snapshotted chrome hide/restore + separate tab-state persistence), extended `FwWorkbench.{h,cpp}` (activate builds/mounts/hides idempotently, deactivate restores), `FwRibbon` overflow "More commands…" button (via `QTabWidget::setCornerWidget`) + `saveTabState`/`restoreTabState`, tests for chrome round-trip + real-toolbar persistence round-trip.

> Dependency on Plan 02-01: proceed only if `SPIKE.md` records the native verdict — i.e. it contains the literal `native committed`. Do not proceed merely because Plan 02-01 ran.
