<objective>
Deliver RIBBON-02 — the single context switch a SolidWorks user notices most: entering a sketch auto-activates the Sketch tab, leaving restores the previously active tab. Implement `FwRibbonContext` as a scoped subscriber to `Gui::Application::Instance->signalInEdit`/`signalResetEdit` (event-driven, NOT polling `Control::activeDialog()` — Pitfall 1), identifying a sketch by the view-provider type-name string `"SketcherGui::ViewProviderSketch"` so FreeWorks keeps zero compile/link dependency on the Sketcher module (Pitfall 2). Bind it to the ribbon mounted in Plan 03 via `FwLayout`. After this plan, the sketch→Sketch-tab→restore behavior works against the live edit lifecycle — the final RIBBON-02 vertical slice that makes the ribbon feel like SolidWorks.

Purpose: RIBBON-02 (Success Criterion 4 — active tab switches by context, wired to edit state); CONTEXT D-09 (sketch-edit drives v1 switching) and D-10 (context wins, then restore).
Output: `FwRibbonContext.{h,cpp}` (signal subscriber + tab-switch logic with a testable pure switch function), `FwLayout` wiring to own/install it bound to the mounted `FwRibbon`, CMake additions, GTest for the switch logic.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Application edit signal → FwRibbonContext | Ribbon only *reads* the relayed edit signal (a Gui-layer relay of per-document edit state); never mutates App or the document. |
| FwRibbonContext → Sketcher module | Sketch identity by type-name string only; NO compile/link dependency on `Mod/Sketcher` (additive/merge discipline). |
| context switcher lifetime → signal bus | Scoped `fastsignals` connections stored and released on teardown; no dangling subscription past FreeWorks mode. |
