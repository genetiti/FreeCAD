# Phase 4 — UI Design Contract

> Visual and interaction contract for the PropertyManager Panel phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Platform note:** This is a desktop **C++20 / Qt 6.8** application, NOT a web app. The shadcn/registry gates do not apply. "Design tokens" below map to **QSS layout metrics**, **`QPalette` color roles**, and **`Gui::TaskView` structure** — never web CSS. The hard project rule (LOCKED Phase 1–3 precedent, CONTEXT.md D-04/D-06) is **palette-only color: no hex literals, no `setStyleSheet` color literals**. Final icon art / exact hues / fonts are owned by **Phase 7** (Visual Theme). Only *functional* state colors (active-box pink, ✓/✗ accept-cancel semantics) are in scope this phase.

## Spacing Scale

Declared values (multiples of 4). These are **QSS layout metrics / `QLayout` margins+spacing** for the FreeWorks-hosted container, NOT web spacing. The hosted PartDesign/Sketcher `TaskDialog`s keep their own internal metrics unmodified (SC4); these tokens govern only the FreeWorks container chrome (header, reference-box affordance, rollout outer padding).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap inside the ✓/✗ header; inline padding in a reference-box row |
| sm | 8px | Compact spacing between header controls; gap between a reference box and its picked-item list |
| md | 16px | Default container content margin; spacing between rollout groups |
| lg | 24px | Header band vertical padding region |
| xl | 32px | Reserved (major container section break) — not expected this phase |
| 2xl | 48px | Not used this phase |
| 3xl | 64px | Not used this phase |

**Exceptions:**
- **Header band height:** the green-✓ / red-✗ accept/cancel header is a fixed **32px** band (multiple of 4) so the ✓/✗ controls render at a SolidWorks-proportioned size; this is a layout metric, not a touch target.
- **Reference-box minimum row height:** **24px** per picked reference row so the auto-expand affordance (CONTEXT D-05) reads clearly.
- Hosted `TaskDialog` internals: **inherit upstream metrics unchanged** (do not re-space existing PartDesign/Sketcher panels — SC4 "work unmodified").

## Typography

No new fonts or sizes are introduced this phase (Phase 7 owns the look-alike font stack). Typography is the **inherited application font** at its existing sizes; the contract below records the *roles* the FreeWorks container uses so the checker can validate hierarchy. Weight is expressed via `QFont::Weight`; only **two weights** are used.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (field labels, picked-item text) | inherited app body (~13px) | Normal (400) | 1.4 (Qt default widget metrics) |
| Label (reference-box caption, field captions) | inherited app body (~13px) | Normal (400) | 1.4 |
| Heading (rollout group title `TaskGroup` header) | inherited app body (~13px) | DemiBold (600) | 1.2 |
| Display (PropertyManager panel title in header band) | inherited app body, +1 step (~14px) | DemiBold (600) | 1.2 |

**Weights:** exactly two — **Normal (400)** for body/labels, **DemiBold (600)** for the panel title and rollout group headers (matches SolidWorks' bold rollout captions). No italics, no third weight.

**Source:** No font decisions in CONTEXT (explicitly deferred to Phase 7); roles inferred from `TaskView`/`TaskGroup` existing structure. Sizes are descriptive of inherited defaults, not new declarations.

## Color

Color is **`QPalette`-role-driven only**. No hex values are written into FreeWorks code this phase. The table records which palette role each functional element resolves through. The 60/30/10 framing maps to: dominant = panel surface, secondary = header/rollout chrome, accent = the *functional state signals* (active-box pink, ✓ accept, ✗ cancel).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `QPalette::Window` / `QPalette::Base` | PropertyManager panel background and field surfaces |
| Secondary (30%) | `QPalette::Button` / `QPalette::AlternateBase` | Header band, rollout group (`TaskGroup`) header chrome, reference-box frame |
| Accent (10%) | derived functional-state tones (see reserved-for list) | ONLY the active reference box, the ✓ accept affordance, the ✗ cancel affordance |
| Semantic — picked/highlight | `QPalette::Highlight` / `QPalette::HighlightedText` | A filled reference box's picked-item rows (mirrors Phase 3 rollback-band reuse of `QPalette::Highlight`) |
| Semantic — inactive/greyed | `QPalette::Disabled, QPalette::Text` | Inactive reference box caption / disabled rollout content (mirrors Phase 3 below-tip greying) |

**Accent reserved for (explicit — never "all interactive elements"):**
1. **Active selection-reference box = PINK.** The box the user has clicked into and is currently filling renders with a **palette-derived pink active tone** (a derived/role color, per CONTEXT D-06 — functional state signal, allowed this phase; exact final hue is Phase 7). Pink signals "this box is armed to receive the next pick."
2. **Green-✓ accept** header control → maps to `TaskView::accept()` (CONTEXT D-04). Green = commit/OK semantic.
3. **Red-✗ cancel** header control → maps to `TaskView::reject()` (CONTEXT D-04). Red = cancel/discard semantic.

**Reserved-color rule (official SolidWorks Help, locked by PROP-02 / CONTEXT D-06):** **BLUE is reserved for prompt icons** — it must NOT be used for the active reference box. Active = pink; blue is never the active-box color.

**Destructive:** The ✗ cancel (reject) is the only "discard" affordance; it discards the in-progress edit. There is no irreversible data-destruction action in this phase (every edit is transaction-wrapped — clean undo/redo, CONTEXT D-10), so no separate destructive-confirmation color is required. See Copywriting Contract for the cancel semantics.

**Source:** CONTEXT D-04 (✓→accept/✗→reject), D-05/D-06 (pink active box, blue reserved), PROP-02; codebase palette-only precedent.

## Copywriting Contract

The hosted PartDesign/Sketcher `TaskDialog`s supply their own per-command field labels verbatim (SC4 — work unmodified). The copy below governs only the **FreeWorks container chrome** and the **states FreeWorks owns** (empty/no-command, the ✓/✗ affordances, cancel semantics). Copy must be terminology-faithful to SolidWorks but must contain **no "SolidWorks" identifier string** (LOCKED fork rule).

| Element | Copy |
|---------|------|
| Primary CTA (accept) | **"OK"** — green ✓ header control; tooltip: "Accept (Enter)". Maps to `TaskView::accept()`. |
| Secondary CTA (cancel) | **"Cancel"** — red ✗ header control; tooltip: "Cancel (Esc)". Maps to `TaskView::reject()`. |
| Empty state heading | **"No command active"** |
| Empty state body | **"Select a feature or start a command to edit its properties here. Double-click a feature in the tree to edit it."** (points the user at the FLOW-01 / TREE-03 entry paths) |
| Error state | **"This edit could not be applied."** + recovery path: **"Adjust the highlighted field and try again, or press Cancel to discard."** (Field-level validation copy is owned by the hosted `TaskDialog`; FreeWorks shows only the container-level fallback.) |
| Reference-box prompt (active/empty) | **"Click here, then select geometry in the graphics area"** (shown in the active pink box when it holds no picks yet) |
| Reference-box clear | **"Clear"** / per-row **"Remove"** (the clear/remove affordances required by PROP-02) |
| Destructive confirmation | **Cancel edit:** no modal confirmation required — Cancel (✗ / Esc) discards the in-progress edit and the transaction rolls back cleanly (undo-safe, CONTEXT D-10). No data is permanently destroyed, so no "Are you sure?" prompt. |

**Keyboard semantics (SolidWorks, override FreeCAD defaults — CONTEXT D-10), surfaced in tooltips above:**
- **Enter → accept (OK / ✓)**
- **Escape → cancel (Cancel / ✗)**
- **Tab → advance to the next field / reference box**

**Source:** CONTEXT D-04, D-05, D-10; PROP-01/PROP-02; SC4. "No SolidWorks string" = LOCKED fork rule (CONTEXT, CLAUDE.md).

## Interaction Contract (phase-specific, desktop)

This section captures the interaction behaviors the checker and executor need beyond static tokens. (Web phases skip this; a Qt PropertyManager needs it.)

| Interaction | Contract |
|-------------|----------|
| Visual focal point | **Primary visual anchor:** the green-✓ / red-✗ header band (the commit/cancel decision point). **Secondary focal point:** the active **pink** reference box (where the user's next action is armed). All other chrome (rollout headers, field labels) is subordinate — the executor must not let hosted-panel content out-emphasize these two anchors. |
| Panel reveal | Panel appears **left-docked** (`Fw_PropertyManager` dock) when a command/edit starts, event-driven via `Gui::Control` + `signalInEdit` (CONTEXT D-07). Slide animation is OPTIONAL polish (`QPropertyAnimation`, only if low-risk + cross-platform-clean); instant reveal is acceptable for MVP (CONTEXT D-08). Slide FEEL → live checklist. |
| Modality | **Non-modal / semi-modal** — geometry stays pickable while the panel is open; model previews live (PROP-01, CONTEXT D-07). Fully-modal is explicitly REJECTED (REQUIREMENTS Out-of-Scope). |
| Rollout groups | Collapsible `TaskBox`/`TaskGroup` rollouts reused from `TaskView` (CONTEXT D-04); dynamic options appear/disappear by choice. |
| Reference box — activate | Click into a box → box becomes **active (pink)**; arms it for the next pick (CONTEXT D-05). |
| Reference box — fill | Pick geometry in 3D view → box **fills**, picked element **highlights** (`QPalette::Highlight`), box **auto-expands** to show added rows (PROP-02). Drives/reads existing `Gui::Selection` only — no parallel selection backend (CONTEXT D-05). |
| Reference box — clear/remove | **Clear** empties the box; per-row **Remove** drops one pick (PROP-02). |
| Tree double-click → edit | Double-clicking a feature in `FwFeatureTree` routes through the existing `ViewProvider::setEdit()` path; because `Control` is left-hosted (D-01), the edit panel lands in the left PropertyManager automatically (TREE-03 / CONTEXT D-09). |
| Sketch → feature flow | On sketch exit (`signalResetEdit`): auto-select the finished sketch as the current `Gui::Selection` profile and land the ribbon on the **Features** tab — but **do NOT auto-start** a feature command (true SW behavior; user clicks Extrude/Revolve with the profile pre-selected) — FLOW-01 / CONTEXT D-11. |
| Transactions | Every edit is transaction-wrapped via the hosted `TaskDialog`'s `openTransaction`/`commitTransaction` — clean undo/redo, no `.FCStd` pollution (CONTEXT D-10). |
