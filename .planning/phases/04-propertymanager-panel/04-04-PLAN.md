<objective>
Deliver the two glue requirements that complete the SolidWorks modeling loop on top of the left-hosted panel: **TREE-03** (double-click a tree feature → edit it in the left PropertyManager) and **FLOW-01** (sketch → feature handoff). TREE-03 is satisfied *for free* by the 04-02 hosting plus the inherited `FwFeatureTree` double-click path — double-clicking a feature triggers the inherited `Gui::TreeWidget` double-click → `ViewProviderDocumentObject::doubleClicked` → `ViewProvider::setEdit(Default)`, whose `TaskDialog` shows via `Gui::Control().showDialog`, which is now left-hosted (D-09) — so this plan only *proves* the routing reaches `setEdit` and lands left, adding no new edit dispatcher. FLOW-01 extends the **existing** `FwRibbonContext` `signalResetEdit` consumer (the same signal that already restores the ribbon tab on sketch exit, FwRibbonContext.cpp:111-121): on a sketch reset, set the just-finished sketch as the current `Gui::Selection` (so a subsequent Extrude/Revolve picks it up as the profile) and land the ribbon on the Features tab — but **do NOT auto-start** a feature command (D-11: true SW leaves the sketch selected and lets the user choose). Sketch identity is the existing `"SketcherGui::ViewProviderSketch"` type-name literal (no Sketcher link — Pitfall 2). **CRITICAL (F5 VERIFIED):** the selection change must be **persistent** — do NOT wrap it in `FwSelectionGuard`, whose destructor clears selection and restores the snapshot on scope exit (FwSelectionGuard.cpp:89-123), which would UNDO the just-set sketch selection (a false-pass: the `addSelection` grep still matches while FLOW-01 actually fails). Use a persistent `Gui::Selection().clearSelection()` + `addSelection(doc, sketch, ..., /*clearPreSelect=*/false)` (the same persistent overload `FwSelectionGuard` uses internally — Selection.h:360) so the finished sketch outlives the handler, and prove it with a post-handler assertion that the selection is STILL the finished sketch after the handler returns.

Purpose: This is the final vertical slice that makes the phase a complete SolidWorks loop — pick a plane → Sketch (panel opens left) → draw → exit (sketch auto-selected, Features tab ready) → Extrude (panel opens left, edit lands left); double-clicking any tree feature re-opens its edit left. Both reuse existing seams (the inherited tree double-click; the `FwRibbonContext` reset consumer) — no new mechanism (04-RESEARCH § Don't Hand-Roll: "a new edit dispatcher" and "auto-launching a feature command" are explicit anti-goals).
Output: the FLOW-01 extension to `FwRibbonContext.{h,cpp}` (the persistent sketch-select step in the existing reset lambda, NO FwSelectionGuard, no auto-launch), the FLOW-01 GTest in `FwPropertyManager.cpp` (with the post-handler persistence assertion), and the TREE-03 routing QTEST in `FwFeatureTreeWidget.cpp`.
</objective>
