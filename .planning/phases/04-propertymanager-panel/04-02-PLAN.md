<objective>
Deliver the PROP-01 core vertical slice: when a feature/sketch command or edit starts, the PropertyManager appears **left-docked** with a green-✓ accept / red-✗ cancel header, and the hosted task panel (rollouts, fields, live preview) runs **unmodified** inside it — end to end, non-modal. Reveal is event-driven via `signalInEdit` (never poll `activeDialog()` — Pitfall 1), reusing the scoped-consumer lifetime discipline of `s_ribbonContext`. Reverse the move in `deactivated()` so stock workbenches keep their right-docked Tasks panel.

Purpose: This is the slice that satisfies ~80% of the phase success criteria (04-RESEARCH § Summary) — the moment the dock is left-hosted, SC4 ("existing PartDesign panels work unmodified") and TREE-03's left-landing come for free; this plan wires the host + the ✓/✗ header + the reveal trigger, the foundation Plans 04-03 (pink box + keys) and 04-04 (tree double-click + sketch→feature flow) build on.
Output: `FwPropertyManagerHeader.{h,cpp}` (new), `FwLayout::mountPropertyManager()`/`unmountPropertyManager()` + the `signalInEdit` reveal consumer (added to `FwLayout.{h,cpp}`), the `FwWorkbench` lifecycle wiring, additive CMake, and the extended offscreen QTEST asserting left placement + `taskPanel()` reachable + accept/reject fire + rollouts intact + saveState round-trip.
