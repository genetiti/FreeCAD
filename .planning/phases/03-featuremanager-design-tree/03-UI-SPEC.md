# Phase 3 — UI Design Contract

> Visual and interaction contract for the FreeWorks FeatureManager design tree
> (`FwFeatureTree : Gui::TreeWidget`, mounted in the left `Fw_FeatureManager` dock).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Platform note:** This is a C++20 / Qt 6.8 desktop CAD application, not a web project.
> The shadcn / web-token sections of the template are mapped onto their native-Qt
> equivalents: "components" = Qt widgets (`QTreeWidget` rows, `QStyledItemDelegate`),
> "spacing scale" = layout/metric tokens in device-independent px, "typography" =
> `QFont` roles, "color" = QPalette **roles** (never hex). shadcn is **not applicable**
> (no React/Next/Vite). This contract extends the Phase 2 ribbon contract
> (`02-UI-SPEC.md`) and obeys its discipline verbatim:
>
> - **Color comes from the active `QPalette` / native `QStyle` ONLY — no inline hex,
>   no `setStyleSheet` for color.** (Enforced in code already: see `FwRibbon.cpp:110-114`.)
> - Final pixel-perfect SW theming (exact blue accent, fonts, SW icon art) is **Phase 7**.
>   This phase fixes only the **structure, spacing, states, and interaction affordances**
>   the tree needs to read and behave as a SolidWorks FeatureManager — not the final
>   colors or icon artwork.
> - No "SolidWorks" identifier in source (CI leak-grep, Phase 1 D-03). SW plane *display
>   names* ("Front/Top/Right Plane") are user-facing `tr()` display text per CONTEXT D-08
>   (verify leak-grep scope at plan time — see RESEARCH A2/Open-Q2).
> - Mount target: the left `Fw_FeatureManager` dock placeholder (`FwLayout.cpp:101,125`).

| Property | Value |

## Spacing Scale

Tree layout metrics in device-independent pixels (Qt scales for HiDPI / `devicePixelRatio`
automatically). Multiples of 4 unless an SW-fidelity exception is noted. These are the
**structural metrics the tree contract pins** — they are theme-overridable in Phase 7.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inset padding inside a row (icon-to-text gap, row edge inset) |
| sm | 8px | Vertical breathing room around the rollback-bar separator band |
| md | 16px | Reserved — grouping break if a future node band needs isolation |

Component metric tokens (the values the tree contract actually pins):

| Metric | Value | Usage |
|--------|-------|-------|
| Row height | 22px | Single tree-row height (one feature / sketch / Origin-child). Compact, SW-FeatureManager-dense; ≥ the 16px icon + 2px top/bottom inset. Not a 4-multiple — **SW-fidelity exception** (matches SW's tight tree row rhythm; FreeCAD default tree row ≈ font-driven). Theme-overridable Phase 7. |
| Indent step (per level) | 16px | Horizontal indent added per nesting level (Origin > plane; Feature > sketch). Set via `QTreeView::setIndentation(16)`. Drives the disclosure-triangle column width. |
| Icon slot | 16×16px | Reserved square for each row's leading icon (feature/sketch/plane/Tip). Art deferred to Phase 7; **metric is fixed now** so rows align. Matches the ribbon's small/flyout-row 16px icon (02-UI-SPEC consistency). |
| Disclosure (expand/collapse) control hit zone | 16px wide | The branch indicator column; standard `QStyle` branch indicator, left of the icon slot. |
| Rollback bar band height | 4px | Visual thickness of the draggable roll-back line itself (the drawn separator between the tip row and the row below it). **SW-fidelity exception** (hairline-plus band, distinct enough to grab). |
| Rollback bar grab zone | 8px tall | The cursor/hit region for grabbing the rollback bar (centered on the 4px band) — larger than the visible band so it is easy to seize, per SW. |
| Insertion-line thickness (drag-reorder) | 2px | The horizontal drop-indicator line drawn between rows during a valid drag-to-reorder. **SW-fidelity exception** (standard Qt drop indicator is ~1–2px; pin 2px for visibility). |
| Pointer target min | 22px | Minimum clickable height for any row (= row height); the rollback grab zone (8px) is the one intentionally-smaller-but-augmented target. |

Exceptions (SW-fidelity, all theme-overridable Phase 7): **22px row height**, **4px rollback
bar band**, **8px rollback grab zone**, **2px insertion line**. Each is a sizing constant chosen
so the tree reads and grabs like a SolidWorks FeatureManager rather than a stock FreeCAD tree.
4-multiple tokens (xs/sm/md, 16px indent, 16px icon slot, 16px disclosure) cover all general
spacing.

## Typography

Qt `QFont` roles for tree text. Sizes are points (pt) at 100% scale; Qt scales for HiDPI.
NO custom font family this phase (system UI font). Exactly 2 weights in play — consistent
with the Phase 2 ribbon contract.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Tree row label (feature / sketch / Origin child) | 9pt | Regular (400) | single line, `QFontMetrics` default; **never wrap, never ellipsis-truncate mid-name** — elide at the right edge only if the dock is too narrow (`Qt::ElideRight`) |
| Active / tip-feature row label | 9pt | Semibold (600) | single line — weight is the active/tip affordance until Phase 7 adds the SW accent (mirrors the ribbon's active-tab Semibold treatment, 02-UI-SPEC) |
| Inline-rename edit field (F2) | 9pt | Regular (400) | single line — inherits the row font exactly so text does not visibly jump when the editor opens |

Notes:
- Exactly 2 weights: Regular (400) for normal/below-tip rows, Semibold (600) for the tip
  (active rollback-point) row. No third weight.
- Greyed (below-tip) rows keep Regular 400 — the de-emphasis is a **color-role** change
  (see Color), NOT a weight or size change, so the tree's vertical rhythm stays uniform.
- Row label line height is governed by Qt's `QFontMetrics` at 9pt within the 22px row; no
  numeric line-height override this phase.

## Color

This phase does NOT introduce a final theme (Phase 7 owns the SW blue accent, panel chrome,
fonts, icon art). The tree MUST render correctly on the **current FreeCAD `QPalette`**
(inherits the user's active FreeCAD light/dark theme). The contract here is the 60/30/10
*role assignment* expressed as palette roles, so Phase 7 can re-skin centrally without the
tree's structure changing. **No inline hex, no `setStyleSheet` for color** — same hard rule
the ribbon already follows (`FwRibbon.cpp:110-114`).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `QPalette::Base` (inherited theme tree background) | Tree viewport background behind all rows |
| Secondary (30%) | `QPalette::AlternateBase` / `QPalette::Window` | Alternating-row / panel chrome surfaces; the rollback-bar band surface uses a `QStyle`-derived divider tone (not hex) |
| Accent (10%) | `QPalette::Highlight` + `QPalette::HighlightedText` (inherited; Phase 7 replaces with SW blue) | **Selected row background/text, the rollback-bar line, and the valid drag insertion-line ONLY** |
| De-emphasis (below-tip greying) | `QPalette::Disabled` group, `QPalette::Text` (i.e. `palette().color(QPalette::Disabled, QPalette::Text)` via `Qt::ForegroundRole` on the item, or the delegate's disabled-state paint) | Below-rollback-bar rows are greyed using the **palette's disabled text role** — never a hard-coded grey, never `Visibility` mutation (CONTEXT D-06, RESEARCH Pitfall 3) |

Accent reserved for (nothing else):
- The **selected tree row** (selection highlight — native `QStyle`/palette).
- The **rollback-bar line** (the drawn roll-back separator at the tip boundary).
- The **valid drag-to-reorder insertion line** (the horizontal drop indicator).

Explicitly NOT accent / state contracts:
- **Below-tip greying** = `QPalette::Disabled` text role only (Gui-only, no property write).
- **Invalid drop (BLOCKED)** = NO insertion line drawn + a **forbidden / no-drop cursor**
  (`Qt::ForbiddenCursor`, the standard `QDragMoveEvent::ignore()` affordance) — color-neutral;
  the *absence* of the accent insertion line is itself the negative signal (CONTEXT D-11).
- **Hover pre-highlight** of a row = the native `QStyle` hover treatment from the palette
  (no custom hover color this phase; SW hover feel is tuned in Phase 7).
- **Tip/active-feature marker** = Semibold label weight (Typography) + the existing
  ViewProviderBody Tip icon (icon art deferred to Phase 7). No new accent element.

The tree MUST NOT hard-code any hex color this phase; all color flows through the inherited
`QPalette` / native `QStyle` so it stays correct in light and dark FreeCAD themes and Phase 7
can swap in the SW blue centrally. **No second semantic (destructive) color** — see Copywriting.

## Interaction State Contract

(Native-Qt state contract — the executor implements these via `drawRow`/delegate paint,
drag events, and the inherited item-editor. Color always via palette role per § Color.)

| State | Affordance |
|-------|------------|
| **Row — normal** | Regular 400 label, 16px icon slot, palette `Text` on `Base`. |
| **Row — selected** | Native selection highlight (`QPalette::Highlight`/`HighlightedText`). Reuses `Gui::TreeWidget` + SelectionObserver wiring (CONTEXT D-01) — selection stays in sync with the 3D view. |
| **Row — hover (pre-highlight)** | Native `QStyle` hover state from palette. No custom color this phase. |
| **Row — tip / active rollback point** | Semibold 600 label + existing ViewProviderBody Tip icon. The rollback bar sits **immediately below** this row. |
| **Row — below tip (rolled-back / suppressed)** | Greyed via `QPalette::Disabled` `Text` role (delegate/`Qt::ForegroundRole`). Rows remain present, selectable, and reorderable — only de-emphasized. NEVER hidden via `Visibility` (Gui-only, D-06). |
| **Rollback bar — at rest** | A 4px drawn horizontal band spanning the tree width at the tip boundary (drawn via `drawRow` override per RESEARCH Open-Q3; overlay is the alternative — planner's call, CONTEXT discretion). Uses accent (`Highlight`)-derived tone. |
| **Rollback bar — grab affordance** | 8px-tall grab zone centered on the band; cursor changes to `Qt::SizeVerCursor` on hover over the band to signal vertical draggability (SW roll-back-line feel). |
| **Rollback bar — dragging** | The band follows the pointer vertically, snapping to **solid-feature row boundaries** (snaps to the nearest preceding solid feature when over a sketch/datum row — RESEARCH Pitfall 5). Rows the bar crosses re-grey/un-grey live as it moves. Commit on release drives the real `Body.Tip` in one transaction (CONTEXT D-04/D-05). |
| **Rollback bar — reversibility** | Dragging the bar back down (toward the end) restores forward `Tip`; "Roll to End" sets `Tip` to the last solid feature (RESEARCH Pitfall 4). Fully reversible — matches SW. |
| **Drag-to-reorder — valid target** | A 2px horizontal **insertion line** (accent tone) drawn between rows at the prospective drop position. Standard `QAbstractItemView` drop indicator, restyled to 2px. |
| **Drag-to-reorder — invalid (BLOCKED)** | NO insertion line + `Qt::ForbiddenCursor`; the drop is rejected (`event->ignore()`), no transaction opens. Validity comes from the existing `canDragObjectToTarget`/`canDropObjectEx` ViewProvider gates (CONTEXT D-10/D-11). Allow-and-flag-error is REJECTED. |
| **F2 inline rename** | Reuse the existing in-place item editor (`editItem` → `DocumentObjectItem::setData` → transactioned `Label.setValue`, CONTEXT D-13). The editor is Qt's default item `QLineEdit`, inheriting the 9pt row font; full current label pre-selected on open; Enter commits, Esc cancels. No custom edit widget. |

## Copywriting Contract

Tree row labels come from each object's `Label` (`obj->Label.getValue()`, rendered by the
ViewProviders the tree observes) — they are NOT re-authored here, except the three Origin
plane display-name remaps. The copy this phase owns: the SW plane display names, the
rollback context-action labels, the empty/error chrome, and tooltips. No "SolidWorks" string
may appear anywhere (CI leak-grep, Phase 1 D-03) — the plane names below contain no such token.

| Element | Copy |
|---------|------|
| Primary CTA | n/a — the tree has no single CTA. Its primary interactions are the three direct manipulations: drag the rollback bar, drag a row to reorder, press F2 to rename. |
| Origin node label | `Origin` (the top grouping node; existing `App::Origin`, label unchanged). |
| Plane display names (CONTEXT D-08) | `Front Plane` (XY_Plane), `Top Plane` (XZ_Plane), `Right Plane` (YZ_Plane) — display-text remap only, via `QStyledItemDelegate`; underlying object labels unchanged. (Plane↔axis correspondence A1 — verify in the parity-user check, RESEARCH.) |
| Rollback context-action — roll back | `Roll Back` (right-click on a feature row above the bar; rolls the tip to that feature). |
| Rollback context-action — roll forward | `Roll Forward` (steps the tip one solid feature toward the end). |
| Rollback context-action — roll to end | `Roll to End` (sets tip to the last solid feature; fully restores — RESEARCH Pitfall 4). |
| Tooltip — rollback bar | `Drag to roll the model back or forward` (shown on hover over the bar grab zone). |
| Tooltip — blocked reorder | `Cannot reorder: would place a feature before something it depends on` (transient affordance only; the primary signal is the forbidden cursor + no insertion line — matches SW's "child before parent" block, RESEARCH). |
| Empty state heading | `No active Body` |
| Empty state body | `Create or activate a Body to see its features here.` (Shown when no `PartDesign::Body` is active in the document — the tree is active-Body-scoped per CONTEXT D-07.) |
| Error state | If the active-Body resolution or a row remap fails, the tree falls back to rendering the unremapped live structure (no error dialog); the gap is recorded as a planning note. No user-facing error UI this phase. |
| Destructive confirmation | n/a — no destructive action in this phase. Rename, reorder, and rollback are all transaction-wrapped (clean undo/redo); they mutate existing properties, never delete. Feature deletion is not in scope this phase. |

Behavioral copy / silent-state contract:
- Rolling the bar, reordering, and renaming produce **no toast/confirmation** — the change is
  immediate and visible in the tree + 3D view, matching SW. Undo (Ctrl+Z) reverses each.
- The plane remap and the rollback greying are silent, live, Gui-only presentation changes.

## Registry Safety

"Registry" here = third-party C++/Qt dependencies pulled into the build for this phase, not a
shadcn component registry (not applicable). This phase introduces **no external packages** —
it reuses only in-tree FreeCAD Gui/App classes and Qt 6.8 Widgets (RESEARCH Package Legitimacy
Audit confirms: no npm/PyPI/crate dependency added).

| Registry | Blocks Used | Safety Gate |
|----------|-------------|-------------|
| Qt 6.8 Widgets (in-tree dependency) | `QTreeWidget` (via `Gui::TreeWidget`), `QStyledItemDelegate`, `QLineEdit` item editor, `QDragMoveEvent`/drop indicator, `QCursor` (`Qt::ForbiddenCursor`/`Qt::SizeVerCursor`) | not required (existing project dependency) |
| FreeCAD Gui tree engine (in-tree) | `Gui::TreeWidget` DnD + F2 + `claimChildren` nesting + SelectionObserver; `ViewProviderOriginGroupExtension` (Origin-on-top); `ViewProviderSketchBased::claimChildren` (sketch nesting); `canDragObjectToTarget`/`canDropObjectEx` (DnD validity gates) | not required (existing project dependency; observe-the-DOM, no engine duplication per CONTEXT D-01/D-02) |
| FreeCAD App rollback engine (in-tree, via command-ID/Python string, NOT linked) | `Body.Tip` (PropertyLink), `Body::insertObject`, `PartDesign_MoveTip` command path | not required (existing project dependency). **Fork-isolation gate:** referenced by command-ID / type-name **string literal** + Gui signals only — NO `#include <Mod/PartDesign/...>`, NO `target_link_libraries(... PartDesignGui)` (RESEARCH Pitfall 1, Phase 2 precedent). CI `tools/fw-string-leak-grep.sh` + module-link guard enforce this. |

No third-party shadcn-style block registries are in scope. No network/eval/env-access vetting
applies (no fetched UI blocks, no new vendored library — unlike Phase 2's conditional SARibbon,
this phase vendors nothing). SW plane display names must clear `tools/fw-string-leak-grep.sh`
(they contain no "SolidWorks" token; verify the grep allow-lists `tr()` display text at plan
time — RESEARCH A2 / Open-Q2).
